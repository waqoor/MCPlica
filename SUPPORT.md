# Support policy

MCPlica is community-maintained open-source software and does not include a paid support SLA.
Before requesting help, use the documentation index, troubleshooting guide, release notes, and
known limitations for the exact version you run.

Use a bug report only for a reproducible product defect and include the release tag or commit,
sanitized logs/request IDs, environment, and minimal non-sensitive reproduction. Use the
documentation template for inaccurate or missing instructions. If repository Discussions are
enabled, use them for usage and design questions that are not defects.

Do not disclose vulnerabilities, credentials, proprietary API specifications, generated secret
bundles, or personal data in public support channels. Report exploitable security issues through
the private process in [SECURITY.md](SECURITY.md).

Maintainers prioritize security, data-integrity, active-release regressions, and reproducible
reports. Response and resolution times are goals subject to maintainer availability, not a service
commitment. Older releases may be asked to reproduce on the currently supported release line.
