## Release blocker found in the final hosted head

The merged `master` push produced successful aggregate [CI run
33695151134](https://github.com/yazeedhasan97/MCPlica/actions/runs/33695151134) and [Security run
33695151161](https://github.com/yazeedhasan97/MCPlica/actions/runs/33695151161). Full log and artifact
inspection found that the E2E job was not clean:

- Playwright reported 15 passed, eight intentional project skips, and one flaky WebKit core
  journey. The first attempt remained on "Step 6 of 10" after `POST /builds`; a retry passed, so
  the job exited zero.
- The retained trace shows `StartBuildStep` navigating to the created build and then invalidating
  the broad unbound journey query. That old request returned after navigation; its canonicalization
  effect replaced the URL with step 6 before the build-bound query won.
- A request-level regression added on the corrective branch fails against the old code with one
  post-build journey request lacking `build_id`. The production correction removes that obsolete
  refetch: navigation itself mounts the distinct build-bound query, which validates the
  project/build relationship.
- `failOnFlakyTests` is enabled whenever `CI` is set while retaining two retries for diagnostics.
  A retried browser failure therefore fails the required job instead of becoming green.

Before the correction, the focused WebKit regression failed exactly `Expected: 0, Received: 1`.
After it, ten serial WebKit journeys passed in 2.6 minutes with no unbound post-build request. The
final hosted pull-request results will supersede this local proof; they must be clean before merge.
