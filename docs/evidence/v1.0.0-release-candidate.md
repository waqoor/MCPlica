## Candidate scope

The candidate establishes root SemVer authority, synchronized package/API/runtime/image metadata,
versioned release notes and changelog, support/compatibility/API/Compose/troubleshooting guidance,
repository templates/labels/ownership policy, deterministic documentation checks, and a tag-only
release workflow. The workflow refuses reused identities and requires successful CI and Security
push runs on the exact tagged `master` commit before it builds, scans, pushes, signs, attests, and
publishes source/image artifacts.

The current candidate also corrects the public OpenRouter API root, preserves decoded HTTP response
semantics for compressed provider catalogs, adds the administrator-only Providers UI, and updates
the control plane and generic runtime to MCP SDK 2.1.1 and protocol revision `2026-07-28`. Reviewed
dependency updates are consolidated in this candidate so overlapping Dependabot branches cannot
land mutually stale lockfiles or checksum manifests.

Tracked browser scratch output and superseded agent handoff/evidence notes were removed. Root-level
`.runtime-*` directories are now excluded from both Git and Docker build contexts and rejected by
repository validation if force-added. The empty funding configuration was removed; sponsorship
documentation says to add a platform configuration only after a verified funding channel exists.

fresh teardown/recreate after those fixes; the earlier mixed-project run is not counted.

## Gates that remain external or intentionally unperformed

The release is prepared for review, but publication remains blocked until each applicable item in
the release checklist has evidence:

- successful hosted CI, Security, dependency-review, CLA, and repository-rule checks on the exact
  pull-request head and later on the merged `master` SHA;
- successful hosted Linux repetition of the locally passing dynamic-runtime Docker acceptance;
- effective branch/ruleset, CODEOWNERS, administrator enforcement, private vulnerability
  reporting, Actions OIDC/GHCR permissions, and founder-approved CLA service configuration;
- hardened supported Linux x86-64 target host capacity, access, firewall, Docker-socket boundary,
  private secrets/key escrow, public DNS/TLS/ACME, secure cookies/headers, monitoring/alerts, and
  incident contacts;
- OpenRouter completion/embedding quota and quality beyond the successful authenticated model-catalog
  handshake, real project upstream DNS/TLS/credentials, any selected external OIDC provider, and
  named MCP-client interoperability;
- coordinated encrypted backup plus isolated restore, accepted RPO/RTO, credential decryptability,
  active-runtime recovery, and application rollback rehearsal;
- tag-triggered source/image SBOMs, checksums, Cosign bundle/signatures, GHCR digests,
  provenance/SBOM attestations, and GitHub Release assets.

The repository is private, so GitHub's introduced-dependency review API is unavailable without an
additional repository entitlement. The same required `dependency-review` job now runs frozen
full-graph `pnpm audit` and `pip-audit` checks for private-repository pull requests; public
repositories continue to use GitHub's introduced-dependency action. This keeps the high-severity
gate executable without weakening it into a warning.

The pull-request-target contributor-authorization workflow now recognizes the repository owner,
organization members, explicitly authorized collaborators, and Dependabot from immutable GitHub
event metadata. All other contributors remain fail-closed: they require a successful status or
check from the founder-approved service named by `CLA_STATUS_CONTEXT` for the exact pull-request
head.

Local fixtures, a green pull request, or a successful release workflow must not be represented as
proof of those operator/environment gates.

## Final publication commands after acceptance

After the pull request is accepted, merge without bypass, wait for successful CI and Security push
runs on the exact merge commit, finish the checklist, and then run from a clean checkout:

```bash
git switch master
git pull --ff-only origin master
python scripts/release_version.py --check
git status --short
git tag -s -a v1.0.0 -m "MCPlica v1.0.0"
git push origin v1.0.0
```

Use `git tag -a` only if the project's approved identity policy does not support signed tags. Do
not create a lightweight tag, move/reuse a tag, publish `latest`, push images manually, or deploy
production from this preparation branch.
