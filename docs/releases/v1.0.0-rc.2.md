# MCPlica v1.0.0-rc.2

This release candidate updates the backend, frontend, and runtime together for evaluation and
integration testing. It does not certify a production installation.

## Changes since rc.1

- Integrates the pending fixes and dependency updates through PR #83, including structured rotating
  logs, worker recovery, protected login destinations, and asynchronous build failure feedback.
- Adds per-model AI usage and cost reporting, corrects absent-embedding accounting, and preserves
  SQL NULL for failed AI runs.
- Fixes source pagination, source deletion confirmation, OpenAPI path-level servers, undefined
  security-scheme rejection, and configured embedding-model identity.
- Hardens canonicalization cancellation and cache isolation, execution-lease error handling,
  frontend YAML parsing, and container dependencies.
- Builds the existing MinIO release from checksum-verified official source and runs it as
  UID/GID 10001. Node 26 builds explicitly provision Corepack.

## Upgrade

Read [the upgrade guide](../operations/upgrade.md) and rehearse against a restored non-production
copy. Preserve existing secrets and set `MCPLICA_VERSION=1.0.0-rc.2`. Use the published immutable
digests for all three application images. The Alembic head remains `0025`; this candidate adds no
database migration beyond rc.1.

Retained MinIO volumes need the ownership migration in the
[Compose guide](../operations/docker-compose.md#minio-source-build) before the new non-root
container starts. Back up database, artifact, runtime-root, and secret state together.
New builds require runtime `>=1.0.0-rc.2,<2.0`; update the runtime image alongside the control plane.
Verify login, source ingestion, indexing, build validation, authenticated MCP calls, redeployment,
rollback, and persistence before resuming changes.

## Release authorization and evidence

The owner explicitly authorized the integration merge, prerelease update, and publication of all
three packages. Any single-maintainer merge uses that authorization and is not represented as an
independent review. Required automated checks remain enforced, and any temporary review exception
is restored after the merge.

The release workflow requires successful CI and Security runs for the exact accepted `master`
commit. It publishes backend, frontend, and runtime images only after image scans, then supplies
immutable digests, source and image SPDX SBOMs, checksums, Cosign signatures, and provenance and
SBOM attestations. See [the release process](../maintainers/releasing.md) for verification.

## Boundaries

The supported deployment remains single-host Linux x86-64 Docker Compose. External OpenRouter
access, model behavior, production DNS/TLS, host hardening, backup restoration, and operational
readiness require acceptance in the operator's environment. Deterministic E2E provider fixtures
do not establish live-provider readiness. See [the compatibility matrix](../compatibility.md)
and [release checklist](../maintainers/release-checklist.md).
